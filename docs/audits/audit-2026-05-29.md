# Audit complet FibGo — 2026-05-29

Audit indépendant, multi-agents et vérifié de façon adversariale du code Go de
`github.com/agbruneau/FibGo`. Méthode : cadrage (CLAUDE.md / ADR / `arch_test.go`
/ `.golangci.yml` / baselines) → fan-out de finders pondérés par dimension sur
3 rounds (loop-until-dry) → vérification adversariale tri-lentille
(correctness / concurrence-mémoire / contexte-invariant, réfutation par défaut)
→ réconciliation contre les invariants documentés et le tag
`archive/vague-A-bigfft-concurrency` → synthèse.

- **Couverture brute** : 89 findings candidats (rounds : 25 / 35 / 29).
- **Survivants après vérification adversariale** : 23 (65 réfutés / déjà-réglés).
- **Re-vérification manuelle** (chaque correctif appliqué relu sur le code vivant) :
  1 finding supplémentaire réfuté (**F-018**, voir §6).

> **Caveats de méthode (honnêteté).**
> 1. La phase de vérification du workflow a subi de nombreux échecs mécaniques
>    d'agents (« subagent completed without calling StructuredOutput ») : un sous-ensemble
>    des lentilles n'a pas produit de verdict structuré. Chaque finding **retenu**
>    a néanmoins été relu manuellement avant toute action ; aucun correctif n'a
>    été appliqué sur la seule foi du verdict automatique.
> 2. `-race` est **indisponible sur l'hôte** (Windows sans CGO/gcc). Tout finding
>    de concurrence / data-race est **report-only** et listé en §4 pour validation
>    sur WSL/Linux.
> 3. Le `golden` `internal/fibonacci/testdata/fibonacci_golden.json` est resté
>    **immuable** (aucun `-update`).

## 1. Résumé exécutif

**Verdict global.** Base de code **fonctionnellement saine sur le chemin de
production par défaut** : le calcul de Fibonacci est correct (golden + fuzz +
property + le nouveau test DTM-on tous verts). **Aucun bug de correction actif**,
**aucune régression de performance** introduite. Les risques résiduels sont des
**trous de couverture/garde** (un haut sur l'intégration DTM-on), des **dérives
documentaires et de lint**, une **divergence latente vs ADR-0002**, et des items
**concurrence bigfft (A-05)** déjà corrigés dans le tag archive — à **récupérer
plutôt qu'à réécrire**.

**Findings retenus par sévérité :** 0 critique · **1 haute** · 10 moyennes · 12 basses (= 23).

**Top risques.**
1. **F-001 (haute)** — l'intégration DTM-on de `FastDoublingCalculator`
   (décision KEEP d'ADR-0001) n'avait **aucun test de correction** ; une
   régression corrompant le résultat en mode DTM-on passait toute la suite.
   **→ corrigé** (test ajouté, cross-check golden + DTM-off).
2. **F-002 (moyenne, report-only)** — les 4 entry-points `*WithContext`
   (`bigfft/context.go`) **masquent les panics post-condition `fermat` en `error`**,
   en divergence avec ADR-0002. Latent (zéro appelant prod) mais deviendrait actif
   à la migration FFTContext (ADR-0004 §B1).
3. **F-003 (moyenne, report-only, archive)** — gap **A-05** ouvert sur `main` :
   `putByKey` ne valide pas la forme des coefficients avant `copy` (troncature
   silencieuse). Fix existant **uniquement** dans `archive/vague-A-bigfft-concurrency`.
4. **Cluster couverture de gardes** (F-005/F-006/F-007/F-008) : invariants en place
   mais non gardés par un test → une régression naïve passerait silencieusement.
   **F-006/F-007/F-008 corrigés** ; F-005 (module sensible `bigfft`) report-only.
5. **F-009 (moyenne)** — dérive du gate `make lint` (~50 issues production hors
   exclusions documentées). Pièce isolable **F-022 corrigée** ; le burn-down complet
   est **différé** (non chirurgical).

**Bilan correctifs.** 12 findings **corrigés** sur la branche `audit/fixes-2026-05-29`
(2 fixes de code, 1 fix de sécurité multi-shell, 4 tests, 5 corrections doc/commentaire) ;
10 **différés** (report-only) ; 1 **réfuté** à la re-vérification.

## 3. Détail par finding

### Corrigés (branche `audit/fixes-2026-05-29`)

#### F-001 — DTM-on `FastDoubling` sans test de correction · **haute** · Tests & couverture · ✅ corrigé (`4c0300b`)
- **Localisation** : `internal/fibonacci/fastdoubling.go:120-132` (branche `EnableDynamicThresholds`).
- **Preuve** : couverture 0 sur la branche ; seul `dtm_bench_test.go:59` (Benchmark, sans assertion) la touchait ; le golden n'active jamais le DTM.
- **Invariant** : ADR-0001 (DTM = KEEP) reposait sur une intégration non gardée.
- **Correctif** : `internal/fibonacci/dtm_correctness_test.go` — exécute FastDoubling avec
  `EnableDynamicThresholds:true` (intervalle 2 pour déclencher `ShouldAdjust`) sur tout le
  corpus golden, compare à l'oracle **et** au résultat DTM-off. Aucune modif de prod.
  Couverture `CalculateCore` → 82.4 % (branche DTM exercée). Golden inchangé.

#### F-016 — `FromDecimalString` tronquait silencieusement une entrée malformée · **basse** · Correctness · ✅ corrigé (`54ef234`)
- **Localisation** : `internal/bigfft/scan.go:62-64` (`scanWithTemp`, cas de base).
- **Preuve** : `z.SetString(str,10)` ignorait `ok` ; `"12x45"` → `12` silencieux, `err=nil`. Aucun appelant prod (sévérité basse).
- **Correctif** : valider le retour de `SetString` et renvoyer une erreur sur entrée non-vide malformée ; **le contrat `"" → 0` est préservé** (gardé par `TestFromDecimalString_EdgeCases`). Nouveau test `TestFromDecimalString_Malformed` (dont le chemin récursif >1232 chiffres). Hors hot path.

#### F-022 — shadowing du builtin `max` · **basse** · Lint · ✅ corrigé (`8703eae`)
- **Localisation** : `internal/errors/errors.go:116`.
- **Preuve** : `golangci-lint` → `builtinShadow: shadowing of predeclared identifier: max (gocritic)`.
- **Correctif** : `max` → `maxLen` (3 occurrences). Behavior-neutral. `golangci-lint run ./internal/errors/` → 0 issue après fix.

#### F-014 — Help/Values non échappés vers le shell (4 générateurs) · **basse** · Sécurité · ✅ corrigé (`b58d580`)
- **Localisation** : `internal/cli/completion/{bash,zsh,fish,powershell}.go`.
- **Preuve** : le contrat E5 (`escape.go`) couvrait les noms d'algorithmes, mais `f.Help` et `f.Values` étaient splicés **bruts** dans les mêmes contextes de quoting (`compgen -W "%s"`, `Description = '%s'`, `-d '%s'`, `(%s)`). Valeurs actuelles statiques sûres → **risque latent**.
- **Correctif** : router Help/Values via les helpers d'échappement existants
  (`formatAlgoListBash`/`Fish`, `escapeZshSingleQuoted`+nouveau `formatZshValueList`,
  `escapePowerShellSingleQuoted`). **Identité** pour les valeurs statiques actuelles →
  snapshots de complétion inchangés (suite `internal/cli` verte). Nouveau test
  `TestFlagFormatters_NeutraliseHelpAndValues` (injection adversariale via les
  formatters paramétrés, sans muter le `flagRegistry` global).

### Différés (report-only) — patch proposé, non appliqué

#### F-002 — `*WithContext` masquent les panics post-condition `fermat` (divergence ADR-0002) · **moyenne** · Concurrence/mémoire
- **Localisation** : `internal/bigfft/context.go:138-142, 158-162, 187-191, 206-210`.
- **Raison du report-only** : divergence vs un **invariant documenté** (ADR-0002) dans un
  **module sensible** ; chemin chaud `bigfft` → validation golden + benchmark + `-race`
  requise (indisponible localement). Latent : zéro appelant prod aujourd'hui, deviendrait
  actif à la migration FFTContext (ADR-0004 §B1, won't-fix release courante).
- **Patch proposé** : aligner les 4 `recover` sur la politique de `fft.go:64-71` —
  `if isFermatPostConditionPanic(r) { panic(r) }` avant le `fmt.Errorf`. Idéalement
  factoriser le corps du `recover` de `fft.go` dans un helper partagé appelé par les deux,
  et étendre `TestFermatPostConditionPanicClassifier` aux variantes `*WithContext`. À faire
  au moment de réactiver FFTContext, avec validation `-race` (WSL).

#### F-003 — `putByKey` ne valide pas la forme des coefficients (gap A-05) · **moyenne** · Concurrence/mémoire · **archive**
- **Localisation** : `internal/bigfft/fft_cache.go:347-396` (boucle `copy` 378-384).
- **Raison du report-only** : item **bigfft A-05 ouvert sur `main`**, fix existant
  **uniquement** dans `archive/vague-A-bigfft-concurrency` (délibéré). Concurrence/forme de
  cache → `-race` indisponible. Exposition prod nulle aujourd'hui (`transform()` émet
  toujours `n+1` mots ; `Get`/`Put` publics test-only).
- **Patch proposé (récupérer, ne pas réécrire)** :
  ```
  git checkout -b fix/a05-putbykey-shape archive/vague-A-bigfft-concurrency -- internal/bigfft/fft_cache.go
  ```
  réintégrer le garde de forme `for i := range pv.Values { if len(pv.Values[i]) != n+1 { return } }`
  en tête de `putByKey` (avant le lock), re-validation **gated** : golden + benchmark (motif
  nommé) + `go test -race` sous WSL/Linux.

#### F-004 — `IntTo` réalloue le buffer résultat (allocation évitable résiduelle) · **moyenne** · Performance
- **Localisation** : `internal/bigfft/fft_poly.go:91-104`.
- **Raison** : hot path perf-sensitive ; magnitude **corrigée** par la vérification
  (instrumentation F(10M) réelle : ~182 mots de shortfall ≈ 0.17 %, **pas** un facteur 2×).
  26.4 MB/op @10M **bat déjà** la baseline (35.9) → non-régression.
- **Patch proposé** : *ne pas* doubler les slots (prémisse réfutée) ; au plus augmenter la
  marge de pré-dimensionnement de quelques centaines de mots, **avec** benchmark avant/après
  (>5 % = blocage). Sinon laisser tel quel.

#### F-005 — branches anti-bloat A2-05 de `releaseFFTState` non couvertes · **moyenne** · Tests & couverture
- **Localisation** : `internal/bigfft/pool.go:508-515`.
- **Raison du report-only** : **module sensible** `bigfft/pool.go` (pools globaux, routage par
  capacité, décision SA6002) ; la branche non couverte est celle dont le `=nil` garde
  l'invariant d'aliasing — un test allouant ~4 Mo devrait idéalement être validé sous `-race`.
- **Patch proposé** : test allouant un `fftState` avec `cap(tmp/tmp2) > maxPooledFFTTmpCap`,
  `releaseFFTState`, assert `tmp == nil && tmp2 == nil`. À valider `-race` (WSL).

#### F-009 — dérive du gate `make lint` (~50 issues production) · **moyenne** · Lint
- **Localisation** : `.golangci.yml` / repo. Reproduit live (v1.64.8) : `golangci-lint run ./...`
  exit 1, ~50 issues hors `_test` (gocritic ~24, revive ~15, prealloc 6, govet shadow 3,
  unparam 2). Les exclusions documentées (SA6002, etc.) sont correctement appliquées ;
  `go vet ./...` est propre.
- **Raison du report-only / partiel** : un burn-down de ~50 issues sur plusieurs fichiers de
  prod n'est **pas chirurgical** (risque sur `prealloc`/`unparam`) → contraire à la discipline
  de l'audit. **Seule la pièce isolable F-022 a été appliquée.**
- **Patch proposé** : PR dédiée combinant (a) correction des issues stylistiques réelles et
  (b) `exclude-rules` documentées pour les faux-positifs idiomatiques (cf. F-021 : shadow
  `errgroup`/bloc-scoped). Re-lancer `make lint` jusqu'à exit 0. **NE PAS** réécrire la logique
  de F-021.

#### F-012 — `BumpAllocator` ré-acquis/ré-alloué à chaque pas FFT · **basse** · Performance
- **Localisation** : `internal/bigfft/bump.go:55-69`, appelé depuis `internal/fibonacci/fft.go:128-130`.
- **Raison** : hot path, module sensible ; hisser le `ba` hors `executeDoublingStepFFT`
  franchit la frontière `DoublingStepExecutor` (diff non chirurgical). Amorti en régime
  stationnaire (B/op stable vs baseline). **Caveat concurrence** : ne jamais partager un `ba`
  dans `executeParallel3` (non thread-safe).
- **Patch proposé** : pré-acquérir un `BumpAllocator` unique dimensionné pour l'opérande final,
  `reset` par pas, confiné à la phase forward mono-goroutine — **avec** gate benchmark.

#### F-013 — `polyFromNat` alloue `make(nat,m)` pour le dernier coefficient partiel · **basse** · Performance
- **Localisation** : `internal/bigfft/fft_poly.go:60-68`.
- **Raison** : hot path, gain marginal (allocation logiquement nécessaire quand `len(x)<m`).
- **Patch proposé** : à ne traiter que dans un refactor FFT plus large (pool routé par capacité), avec benchmark.

#### F-017 — `TransformCached` : chemin gate→key→get→miss→put non couvert via cette entrée · **basse** · Tests & couverture
- **Localisation** : `internal/bigfft/fft_cache.go:459-485`.
- **Raison du report-only** : **module sensible** (globaux + LRU, invariant `putByKey` backing
  frais, logger atomic) ; un test exerçant le hot path du cache devrait être validé `-race`.
  Primitives déjà couvertes ailleurs.
- **Patch proposé** : configurer le cache global `MinBitLen` bas via `SetTransformCacheConfig`
  (restaurer en `defer`), exercer miss→put→hit ; valider `-race` (WSL).

#### F-020 — famille `getEnv*` test-only · **basse** · Lint
- **Localisation** : `internal/config/env.go:22,32,44,56,71`.
- **Raison du report-only** : la vérification a **réfuté le cadrage « outlier »** — les 5
  helpers sont *tous* test-only (la prod parse inline via `os.Getenv`). Supprimer du code non
  demandé va contre la discipline chirurgicale.
- **Patch proposé** : clarifier l'intention avec le mainteneur (legacy vs à câbler vs à
  supprimer) ; si superflu, supprimer la **famille entière** + tests, pas `getEnvString` seul.

#### F-021 — shadowing `govet` (3 sites, bénins/idiomatiques) · **basse** · Lint
- **Localisation** : `internal/fibonacci/doubling_framework.go:112,119` ; `internal/orchestration/orchestrator.go:54`.
- **Raison du report-only** : **aucun défaut** — patterns Go corrects ; le shadow `errgroup`
  (`g, ctx := errgroup.WithContext(ctx)`) est **requis** pour l'annulation cross-calculator.
  Réécrire serait nuisible.
- **Patch proposé** : `//nolint:govet` ciblé ou `exclude-rule` documentée (dans le cadre de F-009). Ne PAS toucher la logique.
